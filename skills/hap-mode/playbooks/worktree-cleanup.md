### Worktree and simulator cleanup

Use this procedure for requested worktree cleanup and for [ship's](../../ship/SKILL.md#return-to-main-and-clean-up) delivered shipment cleanup. Shipping covers demonstrably task-owned implementation worktrees even when they predate the shipping invocation; it does not authorize a repository-wide sweep. A broader disk cleanup request defines its own scope. Other storage remains separate scope.

1. **Inventory.** Resolve `HAP_MODE_DIR` through the runtime contract. Read paths, branch refs, HEADs, locks, and prunable state from `git worktree list --porcelain` (use `-z` for machine parsing). Run the existing `"$HAP_MODE_DIR/scripts/worktree-audit.sh" -b <verified-remote/default> [repo-path]` for supporting evidence. Pass the actual fetched destination; the helper's default-ref fallback, best-effort fetch, ancestry column, and name-based GitHub PR hints do not prove delivery. Do not scan a global transcript store. Record `df -h /` only for a disk-space request.
2. **Prove ownership and delivery per candidate.** Match the inventory's canonical path and repository/common Git directory, full branch ref, and HEAD to the requested task's conversation or host task/worktree records, plus the exact PR repository/head branch/head SHA or directly delivered commits. A similar name, old age, absent remote branch, or generic shared ancestry proves neither ownership nor delivery. Detached worktrees need explicit task/path provenance and an identified shipment commit; otherwise retain them. A temporary tree created by ship has known provenance but still needs all preservation gates below; inspect any commits it gained.
   - For a PR, verify the selected host reports **merged**, record the original merged head and merge result, fetch the actual destination, and verify the result is reachable there with `git merge-base --is-ancestor MERGE_RESULT FETCHED_DESTINATION`. A closed or queued PR is not delivered. A PR merged into an intermediate stack branch needs proof that its result was subsequently delivered to the intended destination; otherwise retain it.
   - For merge/fast-forward delivery, prove the candidate tip is delivered by ancestry. For squash/rebase delivery, ancestry of the original head in the destination is not required: use authoritative merged-at-original-head host evidence plus the delivered merge result. In either case require the local tip to equal or be an ancestor of that recorded original head (`git merge-base --is-ancestor LOCAL_TIP ORIGINAL_HEAD`), with the ownership mapping above. Never use a branch name, squash commit message, matching patch alone, or `MERGED` hint as a substitute. Preserve a tip with extra commits, including an empty commit, even if its files match the shipped tree. If original-head objects or reliable host evidence are unavailable, retain and explain.
   - For direct Git delivery, require the recorded scoped shipment tip and candidate tip to be reachable in the freshly fetched remote destination, and prove the checkout belongs to that task. An unpushed local merge is insufficient. Removing a delivered worktree does not authorize deleting its local-only branch; follow ship's branch policy separately.
3. **Preservation gates.** Retain the primary repository checkout, default/release/protected branches and their worktrees, unrelated or ambiguous candidates, missing/unreadable paths, and locked/prunable entries. Preserve any branch or checkout needed by an open/unmerged stack descendant until safely retargeted or merged. Recheck staged and unstaged changes, untracked **and ignored** files, submodule dirt, and in-progress merge/rebase/cherry-pick/revert/bisect operations. Use `git -C PATH status --porcelain --untracked-files=all --ignored --ignore-submodules=none`; any output or failure means retain. Untracked scratch and ignored build artifacts are local state, not automatic deletion permission. Do not stash, reset, clean, unlock, or discard files to make removal possible.
4. **Prove non-use.** Check the available host's task/thread/worktree inventory, pinned or ongoing conversations, and active workers, including child workers and background jobs using the checkout. Transcript recency and a clean Git status cannot establish idleness. Do not fan out agents unless authorized. Retain an active shipping worker's own checkout even after switching its branch or changing the shell directory. A host binding remains active until its supported lifecycle releases it. If usage or host ownership cannot be established, retain with that concrete limitation. Do not terminate workers, detach threads, archive conversations, or change host protections just to permit cleanup.
5. **Remove before deleting branches.** Immediately recheck path/repository identity, branch/HEAD, status/operations, dependencies, locks, and host usage for each approved candidate. Coordinate with its owner so no writer can resume during removal; if that cannot be assured, defer. For host-managed worktrees, discover and use the supported host removal lifecycle; honor active-worker, main-worktree, lock, and dirty-state refusals. If that lifecycle is unavailable or refuses, retain; never fall back to Git or filesystem deletion to bypass it. For an unmanaged worktree, run `git worktree remove -- PATH` from a surviving checkout outside the target. Never use force flags, `rm -rf`, manual Git metadata removal, or prune to bypass a refusal. Confirm the path and inventory entry are gone, then let ship recheck local/remote branch deletion eligibility. Retained worktrees retain their associated branches. A path already absent is not permission to prune stale host state; report it for reconciliation.
6. **Defer safely.** When the shipping worker cannot remove its own active worktree, finish delivery and record a local/private cleanup receipt outside that worktree, or in the host task record. Include repository identity, task/PR URL or direct shipment identity, verified remote/destination, original head and delivered result SHAs, canonical path, full branch ref and observed tip, retained branch refs, and the specific blocker. Do not commit machine paths or private task data into public sources. Give a concrete continuation: after the owner finishes and the host releases the binding, resume cleanup for this receipt from a surviving checkout. Re-fetch and revalidate **all** ownership, delivery, tip/status, stack, protection, and usage gates; a receipt is evidence, not a deletion command or authority for other trees. Reused paths/branches or changed tips require fresh proof. A later cleanup of the same authorized shipment needs no new shipping action or version bump. Do not schedule a job or start another worker without authorization.
7. **Report.** List removed and retained paths separately with their branch/HEAD and evidence or concrete reason (for example, extra commit, ignored file, open child PR, active task, unknown usage, host refusal). Include deferred receipt location and next step. Confirm final worktree inventory and branch outcomes. For a disk-space request, also report `df -h /` before/after. Partial cleanup does not invalidate verified delivery; never report retained worktrees as removed.

Inspect simulators, caches, or other storage only when requested, using appropriate platform tools and their deletion gates. Never delete unrelated application state because it is large.
